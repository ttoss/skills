# Chase

`/flow <project id> --chase` runs the [Chase](https://raw.githubusercontent.com/ttoss/ttoss/main/docs/website/docs/engineering/workflow/routines.md#standard-routines): one digest of what needs a person, in the sections the workflow names, ordered by what ages fastest. It works on no task and writes nothing to Flow but its run, recorded in section 0 with `agent: flow chase`; it needs `get-next`, `get-task`, `get-project`, `list-tasks`, `list-agent-runs`, `upsert-agent-run`, the code host's read of changes and the delivery's tool.

**Read each section by its own query, sorted so that what qualifies comes first, and stop at the first row that does not**: never the whole graph. A page whose last row still qualifies is read on, by the next page where the tool pages, else the section says it may be incomplete. A task appears once, in the first section that takes it.

1. **Critical bugs**: `list-tasks` with `tag: [bug]`, `priority: [very_high, high]` and the open statuses, and `list-tasks` with `priority: [very_high]`. For each, what holds it: a wait (its reason, and who it is `on`), a task that `blocks` it, a `running` run holding it (`list-agent-runs` with `task` and `status: [running]`), or nothing ("ready, nobody took it").
2. **Changes waiting to be integrated by a person**: on the code host, each repo's open, non-draft changes whose checks and the review the `Review` parameter names passed; keep a change whose task (its URL in the description) is `waiting` on a person.
3. **Overdue waits, checks and no owner**: `get-next` with `slice: waiting`, `assignee: ["any"]`, `sort: until` and `limit` 50, kept while the wait is `external` and its `until` has passed (overdue by that many whole days); then the same with `sort: review_due_at` and `review_due: true`, kept while the wait has no `until` (no chase date, untouched for a week). `get-task` each task kept, for whom its wait is `on` and its `implements` changes, and sort it:
   - **Overdue checks**: its `implements` change is integrated (the code host says so), so what is left is its check; also every task `get-next` with `slice: date_came` still lists, since the tick's check children would have taken it;
   - **No owner**: its wait is `on` nobody;
   - **Overdue waits**: the rest.
4. **Old decisions**: `get-next` with `kind: [decision]`, `status: [waiting]`, `assignee: ["any"]` and `review_due: true`, the one with the most `unblocks` first.
5. **Stale sessions**: `list-agent-runs` with `project`, `status: [running]` and `limit` 100; keep a run whose `agent` is not `flow tick`, `flow child` or `flow chase` (the tick closes stale children itself), started longer ago than the `Runtime`'s `Stale after` (default 4 hours); each open task in its `works_on` is a line under the person who recorded it (`by`).
6. **Health**: the changes the code host integrated since the newest earlier `flow chase` run started, `get-next`'s ready `total`, and how many ready tasks a stale session holds.
7. **Write the digest** in the project's language: a title line with the date; the sections in this order: Critical bugs, Changes waiting to be integrated by a person, Overdue checks, Old decisions, Stale sessions, Overdue waits, No owner. Each line is `[title](url) — <who acts> — <what they do, from the wait's reason or the change>`, longest waiting first (decisions by `unblocks`). At most five lines a section, then `+N more`; an empty section is left out, except Critical bugs, which says there are none. The health line last. Who acts is the person the wait is `on`, the run's `by`, or the person the `Merge rule` names; mention them by the delivery's handle for their email (`get-project`) where the delivery supports mentions, else by email.
8. Deliver it where the Chase's row in `Routines` says, such as a channel; otherwise it is the run's final message, which the runtime delivers to the routine's owner.
9. The `Runtime`'s acts on every run, then close the run. The final message is the digest, or one line naming where it went and how many lines it holds.

Never move a task, change a wait or its `until`, or send anything but the one digest.
