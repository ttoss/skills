# Calibration

`/flow <project id> --calibrate` runs the [Calibration](routines.md#standard-routines): it hands a person a random sample of what the loop integrated on its own to review in depth, and compares how the loop behaves on each model. It works on no task the loop holds; its run is recorded in section 0 with `agent: flow calibration`, and it needs `list-agent-runs`, `list-tasks`, `get-task`, `upsert-tasks`, `upsert-agent-run` and the code host's read of merged changes.

1. **Window.** From the start of the last `flow calibration` run (`list-agent-runs` with `project` and `agent: flow calibration`), else seven days ago, to now.
2. **Sample.** The changes merged in the window, in the project's `Repos`, by the identity the tick integrates with: the loop's own integrations. Draw the `Calibration` share of them at random (default one in ten, at least one when any merged), never by size, title or how risky one looks. For each change drawn, `upsert-tasks` one task: title `Review in depth: <change title>`; `waiting` (`external`, `on` the `Calibration` reviewer, by default the person `Renewal` names, `until` now, so the next Chase sends it); the change's URL as its `source` reference and as `dedupe_on`; and a body of three lines: read the diff against its task's acceptance; look for a check it weakened, a scope it widened, a next change it made harder; close this task with the verdict, and write each finding as a task of its own with this change as its `source`.
3. **Behavior per model.** Two windows: the last 14 days and the 28 before. From `list-agent-runs` with `project` and `agent: flow-manager child`, per model (`group_by: model`, then `group_by: task` with `model`): the runs per task, the share closed `failed`, and the cost per task. From the `changes` of the tasks closed in each window, read by a subagent that returns only the counts: the tasks that reached the round limit (a move to `waiting` on a person naming it) and those the Verify stage sent back to `active`. A model that first ran in the last 14 days is compared with the one it replaced, as the parameters file's history shows. A measure worse by the `Calibration` threshold (default a quarter) → one `incubated` task, tagged `calibration`, with both windows' numbers and the runs they come from (GTF-C1), unless an open task already reports it (`list-tasks` with `tag: [calibration]`).
4. The `Runtime`'s acts on every run, then close the run. The final message: the sample by task `url`, then one line per model with its numbers, or `no regression`.

Never move or close a task the loop holds, review a change yourself, or change a model, a parameter or a routine.
