# ttoss skills

Agent skills shared across ttoss projects. The Flow skills are built on [Get Things Flowing](https://flow.ttoss.dev/docs/agents/protocol.md) (GTF), the method Flow defines for agents.

**Rule of thumb:** GTF is a general method, for anyone in any profession; these skills are for **product development** — code, PRs, CI, review, releases, deploys; a project is one product. A rule true of any work belongs in GTF, one true of product development in general belongs here, and one true of a single product is that project's parameters.

The loop is generic across products: how a project merges, releases and proves work done are **extension points** each project answers in its own parameters, which `flow-setup` defines with the user. GTF always wins; where a project answers an extension point, its answer is followed; the skills supply the cycle and a default for every point left empty. Every skill here writes in a [terse voice](skills/flow-manager/references/voice.md) by default, to spend as few tokens as possible; a project sets `Voice: normal` to turn it off. Each one lives in `skills/<name>/SKILL.md`; install it with the [`skills` CLI](https://github.com/vercel-labs/skills) (`npx skills add ttoss/skills`), which records it in the consuming repo's `skills-lock.json`.

| Skill | What it does |
| --- | --- |
| [`flow-manager`](skills/flow-manager/SKILL.md) | Manages a project's autonomous delivery loop from its Flow graph: one tick reads the graph, merges by the project's merge rule, runs its release procedure, verifies by its closing evidence and delegates every ready task to a child agent run. Run it with `/loop 10m /flow-manager` or from a recurring routine; a task id, `tag:<name>` or a description focuses it on part of the graph, `--max-runs N` caps child runs and `--voice normal` turns off the terse default for one run. |
| [`flow-setup`](skills/flow-setup/SKILL.md) | Sets a repository up for the loop, or audits it again: installs the skills, walks the user through the project's extension points (merge rule, release procedure, closing evidence, verification target, human-reserved decisions, decision gate, findings rule) from what the repo already says, removes rules that only restate GTF or the skills, proposes the Flow standing decision and opens a PR for review. |
| [`flow-friction`](skills/flow-friction/SKILL.md) | Files friction met in a skill, the Get Things Flowing method or the Flow MCP tools as an issue here, deduplicated against open issues, and links it back to the Flow task. |
| [`token-audit`](skills/token-audit/SKILL.md) | Finds where a project's Claude Code sessions waste tokens, from measurements: the instruction corpus every session loads (`scripts/measure_instructions.py`), scoped rules stacking in busy packages, real session usage (cost, context growth, cache rewrites, PR wake-ups), each routine's model against its work, and tool payloads that bloat context. Ranks fixes by measured saving and changes nothing without the user's word. |
