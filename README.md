# ttoss skills

Agent skills shared across ttoss projects. The Flow skills are built on [Get Things Flowing](https://flow.ttoss.dev/docs/agents/protocol.md) (GTF), the method Flow defines for agents.

**Rule of thumb:** GTF is a general method, for anyone in any profession; these skills are for **software delivery**, in any project: a change goes through its gates, is integrated, released and verified, whatever the code host or the kind of delivery. A rule true of any work belongs in GTF, one true of software delivery in general belongs here, and one true of a single product is that project's parameters.

The [delivery process](skills/flow-manager/references/process.md) is written once, here: seven stages, one owner each, and the transitions between them. How a project integrates, releases and proves work done are its answers to the process's [parameters](skills/flow-manager/references/parameters.md), which `flow-setup` defines with the user. GTF always wins; where a project answers a parameter, its answer is followed; the skills supply a default for every parameter left empty. Each skill lives in `skills/<name>/SKILL.md`; install it with the [`skills` CLI](https://github.com/vercel-labs/skills) (`npx skills add ttoss/skills`), which records it in the consuming repo's `skills-lock.json`.

| Skill | What it does |
| --- | --- |
| [`flow-manager`](skills/flow-manager/SKILL.md) | Runs a project's delivery loop from its Flow graph: one tick reads the graph, integrates by the project's merge rule, runs its release procedure and the checks that came due, and delegates ready tasks to child agent runs it records, then ends in one line. Any scheduler fires the tick: a recurring routine, a cron or CI job running the agent headless, or `/loop 10m /flow-manager`; a task id, `tag:<name>` or a description focuses it on part of the graph, and `--max-runs N` caps child runs. |
| [`flow-setup`](skills/flow-setup/SKILL.md) | Sets a repository up for the loop, or audits it again: installs the skills, walks the user through the project's parameters (runtime, intake, ready brief, decisions, before proposing, review, merge rule, release procedure, closing evidence, delivery kinds) from what the repo already says, removes delivery rules that only restate GTF or the skills, writes the entry section every session reads, proposes the Flow standing decision and opens a PR for review. |
| [`flow-friction`](skills/flow-friction/SKILL.md) | Files friction met in a skill, the Get Things Flowing method or the Flow MCP tools as an issue here, deduplicated against open issues, and links it back to the Flow task. |
| [`token-audit`](skills/token-audit/SKILL.md) | Finds where a project's Claude Code sessions waste tokens, from measurements: the instruction corpus every session loads (`scripts/measure_instructions.py`), scoped rules stacking in busy packages, real session usage (cost, context growth, cache rewrites, PR wake-ups), each routine's model against its work, and tool payloads that bloat context. Ranks fixes by measured saving and changes nothing without the user's word. |
