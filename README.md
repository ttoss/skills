# ttoss skills

Agent skills shared across ttoss projects. The Flow skills are built on [Get Things Flowing](https://flow.ttoss.dev/docs/agents/protocol.md) (GTF), the method Flow defines for agents.

The ttoss [Agentic Workflow](https://ttoss.dev/docs/engineering/workflow) is GTF applied to product development, and these skills are how an agent runs it. Its [delivery process](https://github.com/ttoss/ttoss/blob/main/docs/website/docs/engineering/workflow/process.md), [parameters](https://github.com/ttoss/ttoss/blob/main/docs/website/docs/engineering/workflow/parameters.md) and [routines](https://github.com/ttoss/ttoss/blob/main/docs/website/docs/engineering/workflow/routines.md) are read from ttoss/ttoss's default branch, so an edit to them belongs there; which level a rule belongs to, and what wins when two disagree, is [precedence](skills/flow-setup/SKILL.md#precedence) in `flow-setup`. Each skill lives in `skills/<name>/SKILL.md`; install it with the [`skills` CLI](https://github.com/vercel-labs/skills) (`npx skills add ttoss/skills`), which records it in the consuming repo's `skills-lock.json`.

| Skill | What it does |
| --- | --- |
| [`flow`](skills/flow/SKILL.md) | Runs a project's Agentic Workflow from its Flow graph, with its arithmetic in `scripts/` (the parameters, the code host through `gh`, the tick's snapshot and planner, the Chase's digest, the Audit's lines, a `check` of the Flow API key they read with): one tick reads the graph, reviews and integrates by the project's merge rule, runs its release procedure and the checks that came due, and delegates ready tasks to child agent runs it records, then ends in one line. The project's routines fire the tick; a task id or `tag:<name>` focuses it on part of the graph, `--max-runs N` caps child runs and `--chase` sends, instead of a tick, the daily digest of what needs a person, in sections ordered by what ages fastest, closing with the flow's health: each queue's arrivals and departures, the person queue's trend, rework and failure demand. |
| [`flow-setup`](skills/flow-setup/SKILL.md) | Sets a repository up for the Agentic Workflow, or audits it again: installs the skills, walks the user through the project's parameters (runtime, intake, ready brief, decisions, before proposing, review, merge rule, release procedure, closing evidence, delivery kinds) from what the repo already says, removes delivery rules that only restate GTF or the skills, writes the entry section every session reads and the workflow map people read (`AGENTIC_WORKFLOW.md`), proposes the Flow standing decision and opens a PR for review; once it merges, creates the routines that fire the runs, and `routine <name>` adds a project's own. |
| [`flow-friction`](skills/flow-friction/SKILL.md) | Files friction met in a skill, the Get Things Flowing method or the Flow MCP tools as an issue here, deduplicated against open issues, and links it back to the Flow task. |
| [`token-audit`](skills/token-audit/SKILL.md) | Finds where a project's Claude Code sessions waste tokens, from measurements: the instruction corpus every session loads (`scripts/measure_instructions.py`), scoped rules stacking in busy packages, real session usage (cost, context growth, cache rewrites, PR wake-ups), each routine's model against its work, and tool payloads that bloat context. Ranks fixes by measured saving and changes nothing without the user's word; `--routine` runs it as a Flow project's weekly audit, filing each fix as an `incubated` task and reporting the spend on work that did not ship, what became of incubated work and the untriaged inbox. |
| [`instruction-hygiene`](skills/instruction-hygiene/SKILL.md) | Makes a repository's agent instructions short and direct in two passes, each its own PR: strips decision history, provenance and measurements (the Flow graph holds the record), then condenses what is left into imperative instructions, keeping every rule, path, threshold and the headings other files or code comments point at (`scripts/heading_refs.py` lists them and reports the ones a rewrite broke). Applies what `token-audit` proposes for the instruction corpus, on the user's word. |
